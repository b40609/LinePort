# 三階段開發項目對照

2026-10-09，v0.7.0。以下以原需求的「實作／設計／評估／研究」分別列出成果，研究完成不等於平台能力已支援。驗證採 Mock 與獨立目錄，未使用真實帳號發訊。

| 階段／原項目 | 成果 | 支援範圍與限制 |
| --- | --- | --- |
| 一：首次引導、空白狀態、權限與操作說明 | 已實作 | 三步引導、只讀檢查、必要／進階選項；權限檢查不證明能送達 |
| 一：規則摘要、模擬預覽 | 已實作 | 每個來源、作者／文字／媒體／時段／回覆；不發訊 |
| 一：待送、成功、失敗與等待原因 | 已實作 | 各配對獨立狀態及原因；成功指平台回應已保存，非對方已讀 |
| 一：不明結果人工處理 | 已實作 | 停止後逐筆確認收到／略過、保留決策；沒有整批重送 |
| 一：安全診斷 | 已實作 | 允許清單排除憑證、全文、身分／路徑與任意錯誤 |
| 一：版本下載、更新說明與 SHA-256 | 已建立 | 固定 tag 原始碼 ZIP；手動更新，沒有自動更新 |
| 一：設定備份／還原 | 已實作 | 不含憑證；先驗證並保留原設定，不取代完整資料備份 |
| 二：增長檢查、容量／封存與保留政策 | 已檢查並實作保守停止及封存 | 保留全部待送、去重與不明證據；封存重新驗證，達上限不自行清理；[政策與壓縮設計](DATA-RETENTION.md) |
| 二：DPAPI／Yomi 儲存與回復遷移評估 | 評估完成，Bot Token 保護已實作 | CurrentUser 選用；Yomi 獨立 E2EE 儲存不能只替換 credentialStore，LINE 全面加密尚未遷移；[評估](RESEARCH-0.7.0.md) |
| 二：來源與目的工作隔離 | 已實作 | 各來源獨立讀取，目的公平序列化；同一目的仍受慢請求影響 |
| 二：斷線、程序中止、磁碟失敗與積壓測試 | 已通過模擬 | 包含獨立子程序中止；沒有多日／朋友端／硬體斷電驗證 |
| 三：圖片與檔案、限制／保護／暫存／失敗 | 評估完成，Telegram 同 Bot 轉送已實作 | file_id 重用、無下載暫存；10 MB 圖片、50 MB 檔案、1,024 字元說明；跨 LINE 不支援 |
| 三：回覆關聯 | 已實作，預設關閉 | 同配對 ACK ID 對照跨重啟；無對照正常發送一次，不補送原訊息 |
| 三：規則複製、搜尋、範本 | 已實作 | 暫停複本、通知 關鍵字範例、每來源固定作者 ID |
| 三：時段排程評估 | 評估完成並實作 | 台北時間；明確選擇 hold 保留／skip 留略過證據，預設關閉 |
| 三：Discord／Slack 官方整合研究並選一個 | Discord 目的已完成 | 官方 REST 一般伺服器文字頻道、權限說明、限流與不明處理；沒有 Discord 來源／媒體，Slack 未實作 |
| 三：LINE 社群可行性 | 評估完成，未支援 | Yomi 模組存在不代表穩定可用，不宣稱已支援 |

原清單的保守實作、設計與評估已交付。這不表示所有候選功能皆已開放。若後續要跨 LINE 圖片、全 LINE 憑證加密或容量壓縮，需依研究文件完成額外工程；涉及刪除、不可逆遷移或資料庫 Schema 時須先取得明確確認。

下一個產品決策是實際訊息格式及來源→目的配置：先固定指定發訊者 ID，逐來源用去識別化樣本核對內容條件，再決定圖片、回覆及時段是否啟用。[設定範例](ROUTING.md)
