# 0.8.5 初始化失敗診斷修補（2026-10-22）

此頁保留第一輪診斷包的歷史說明。後續已重現並修正實際 E2EE 缺陷，請使用 [v0.8.6 修補包說明](RELEASE-0.8.6.md)，不必先安裝本頁的舊診斷包。

本包補上轉送初始化的失敗階段，供 iPad QR 登入後無法啟動轉送時排查。版本仍為 0.8.5；不是已確認修復朋友端故障的版本。舊診斷的 0.8.4 是匯出程式殘留字串，本包已對齊 0.8.5。

## 更新與回報

1. 在舊程式按「停止轉送」，再從舊程式的 `yomi-probe` 目錄執行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\stop-server.ps1`，關閉設定服務。
2. 將本包解壓到另一個新目錄；在新目錄的 `yomi-probe` 執行 `npm.cmd ci --ignore-scripts`，再雙擊根目錄的 `啟動iPad實驗模式.cmd`。
3. 在帳號頁使用同一 iPad 身分已保存的登入；既有規則與轉送紀錄沿用本機資料目錄。若沒有顯示原規則，先確認身分，不要另建重複規則。
4. 按「開始轉送」。若仍失敗，記下路線顯示的「失敗階段」，並到「設定與診斷」匯出新的安全診斷 JSON。新版每條路線都有 `stage`；若沒有，請確認舊服務已關閉並重新整理頁面。
5. 若啟動成功，再於原測試來源發一則新測試文字，人工核對目的是否收到。初次建立基準不補送歷史訊息。

回報安全診斷即可；不需要分享完整資料目錄、登入檔、金鑰或聊天室內容。不要清空轉送紀錄或刪除金鑰。

## 階段判讀

| stage | 失敗位置 |
| --- | --- |
| platform | 平台帳號尚未就緒 |
| resume / e2ee_keys | 背景登入恢復／自身金鑰載入 |
| groups / route_identity | 聊天室確認／紀錄身分核對 |
| destination_e2ee | LINE 目的聊天室加密準備 |
| destination_prepare | 其他平台目的聊天室準備 |
| baseline | 來源首次讀取 |
| journal | 本機轉送紀錄讀寫 |
| unknown | 舊程序或無法識別的階段，不能據此判定根因 |

本輪 224 項自動化測試通過，含故障隔離、重啟不重送及診斷遮蔽。沒有讀取朋友端資料或進行朋友帳號的實機收送，實際故障原因仍待新版診斷確認。
