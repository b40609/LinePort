# 真實平台驗收

適用 v0.7.2。Mock 通過不代表實際平台已驗收；本表在取得專用測試群組、完成平台連結後使用。只使用合成訊息，不保存群友訊息、真實憑證或私人群組 ID 到本文件。

## 準備與範圍

1. 指定 LINE、Telegram 各一個測試來源與測試目的；來源與目的不同，所有群組成員知道會收到測試訊息。
2. 在本機介面連結平台；Token 只輸入本機欄位，勿貼到對話。指定成員從來源發訊，Telegram 來源不要用 Bot 發測試訊息。
3. 先停止轉送，私下匯出設定備份並記下原先啟用的規則。測試時暫停原規則，避免正式路線被啟動；保留原設定與所有待送紀錄。
4. 建立兩條來源規則，各選 LINE、Telegram 測試目的，共四個配對。篩選使用指定發訊者固定 ID 與必要關鍵字「通知」；前綴使用 `[驗收] `。媒體、時段、回覆先關閉。
5. 先模擬正反例，再啟動測試規則；等來源基準完成才送新文字。預檢通過只證明目前可讀取的權限資訊，收送仍需實測。

## 文字與篩選

每則訊息使用不同流水號，例如 `通知 LP-TEST-001，謝謝`。在私人驗收表記錄來源訊息 ID、目的訊息 ID、時間與數量；公開回報只記結果與計數。

| 檢查 | 預期 | 實測結果 |
| --- | --- | --- |
| LINE → LINE | 指定成員通知收到一次，包含前綴 | 未測 |
| LINE → Telegram | 同一通知收到一次 | 未測 |
| Telegram → LINE | 指定成員通知收到一次 | 未測 |
| Telegram → Telegram | 同一通知收到一次 | 未測 |
| 非指定成員傳相同通知 | 兩個目的都不收到，狀態顯示略過 | 未測 |
| 指定成員傳「你好，謝謝」 | 兩個目的都不收到 | 未測 |
| 指定成員通知結尾含「謝謝」 | 兩個目的都收到 | 未測 |
| 不同 ID、相同文字各傳一次 | 每個目的收到兩則 | 未測 |
| 貼圖／沒有文字的 LINE 圖片 | 不轉送；LINE 圖片尚未支援 | 未測 |

## 恢復與送達證據

先核對目的實際訊息，再核對成功數。平台回傳訊息 ID 且紀錄保存成功不代表已讀。重啟後程序計數會歸零，不能只用計數判斷重複。

| 檢查 | 預期 | 實測結果 |
| --- | --- | --- |
| 已確認送達後停止、重啟相同規則 | 舊訊息不重送，新訊息可轉送 | 未測 |
| 停止期間來源新增合成通知，再重啟 | 記錄是否補讀及有無警示；不能承諾完整補送 | 未測 |
| 短暫斷網後恢復 | 來源退避重試，確認沒有重複；發送不明需人工核對 | 未測 |
| 一個測試目的暫時無權限 | 記錄該路線受阻，另一目的是否繼續 | 未測 |
| 24–72 小時小量運作 | 核對送達、重複、積壓、容量及來源警示 | 未測 |

不要為觸發 429 大量發訊，不在真實資料目錄模擬磁碟損壞或強制終止程序。這些故障先使用獨立目錄與 Mock。遇到發送不明立即停止該測試，逐筆到目的核對，再在介面確認收到或略過；不直接重送整批。

## 選用 Telegram 媒體

文字驗收完成後，另建暫停的 Telegram → Telegram 規則，避免與啟用文字規則重複配對。只使用同一 Bot 可取得的合成小圖片／小檔案，另行啟用媒體再測試。若有必要關鍵字，媒體說明也需包含「通知」。圖片最多 10 MB、檔案最多 50 MB，含前綴的說明最多 1,024 字元。

LINE 圖片與跨 LINE 媒體未支援，不列為通過項目；圖片沒有說明時，必要關鍵字會將它篩掉。受保護內容不轉送，大小未知或超限會阻擋路線。

## 結束

停止測試轉送，保存安全診斷及私人驗收證據，將測試規則停用。核對原設定後還原或重新啟用原規則；由使用者決定何時啟動正式轉送。保留測試紀錄與待送證據，不刪資料解除受阻。

只有實際完成並核對目的的項目才能填入「通過」。未測、受阻及平台限制分開列出；不得以 Mock 或預檢替代實際收送結果。
