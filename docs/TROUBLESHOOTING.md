# 疑難排解

查看頁面各來源／配對警示，或 http://127.0.0.1:18766/status。回報時提供版本、phase、stage 與去識別化錯誤；不要上傳 Token、PIN、登入目錄或私人訊息。

| 現象 | 處理方式 |
| --- | --- |
| 手機無授權提示 | 確認同一帳號、允許其他裝置登入；原申請結束後再申請，不要並行登入 |
| data_permissions | 檢查 LOCALAPPDATA、Windows 權限與資料目錄連結；勿改成公開共用目錄 |
| LINE 登入不存在／失效 | 先停止轉送，再恢復或重新手機授權 |
| LINE 已連結但路線初始化失敗 | 查看失敗路線的「失敗階段」及處理提示，再到「設定與診斷」匯出安全診斷。LINE 已連結只表示登入成功，不能證明目的群組加密及來源讀取可用；舊版通用錯誤與未含路線 stage 的診斷不足以確定原因 |
| 可以列群組但收不到 | 等首次基準完成後發全新文字；本輪掃描包含舊訊息。看各路線已處理、新候選、符合條件與條件排除數，並核對指定人員、必要字、排除字及排程。符合條件後仍須看待送／平台接受／發送不明；核對解密失敗與時間警示。已排除訊息不自動重算 |
| e2ee_keys | 缺少帳號加解密資料；停止並重新手機授權 |
| destination_e2ee | 目的加密準備失敗；查看路線提示及安全診斷的 failureReason。2026-10-22 原始碼修補會在恢復登入時補齊非空快取缺少的歷代自身金鑰，尚未封裝到既有 rc.1 EXE。載入修補須停止轉送與設定服務，再啟動新版；保留原金鑰、規則與轉送紀錄 |
| missing_receiver_key／missing_self_key | 分別為缺少目的要求的舊代接收金鑰／帳號發送金鑰；先載入修補後程式恢復金鑰鏈，仍失敗才停止並重新手機授權 |
| missing_group_key | LINE 未提供可用群組金鑰。2026-10-22 原始碼修補會在確認目的群內官方帳號明確不支援 E2EE 時，自動改用相容文字傳送；頁面標示「傳輸加密，無端對端加密」。其他情況仍停止該路線並保留錯誤；確認成員資格及官方 LINE 可收發，保留診斷供排查。既有 rc.1 EXE 尚未包含此修補 |
| Bot 相容文字 | 僅改變送進此目的群組的傳送方式，不讀取或轉送目的 Bot 的訊息；一般目的仍優先使用端對端加密。相容模式目前僅支援文字，啟用圖片／檔案的規則會被阻擋，請停轉後另建純文字規則或關閉媒體 |
| peer_key_mismatch／invalid_group_key | 群組金鑰建立者版本不符／共享金鑰資料不完整或解密失敗；確認官方 LINE 可收發後停止並重啟，仍失敗保留安全診斷 |
| network／timeout／unknown（destination_e2ee） | 連線失敗／逾時先檢查網路後停止並重試；unknown 表示原因尚未識別，匯出診斷供排查，不能直接認定缺少金鑰 |
| baseline | 來源首次讀取失敗；確認網路、來源聊天室成員資格及讀取權限，停止後重試 |
| platform／destination_prepare | 核對涉及平台的帳號連結、聊天室成員及平台權限，停止後重試 |
| LINE 個人不在選單 | 目前只列出好友，官方帳號排除；重新載入群組與好友 |
| 同名群組 | 依選項後方 ID 辨識；新版不要求名稱唯一 |
| 重複／循環規則被阻擋 | 檢查所有啟用規則；不可自我轉送、重複配對或形成回到原來源的路徑 |
| 來源讀取警示／degraded | 該來源採退避重試；檢查連網、登入及時間，其他來源仍可運作 |
| LINE 正在分批補讀歷史訊息 | 每輪最多讀 20 頁，下一輪會接續。若顯示游標無法前進，請保留紀錄並檢查來源歷史 |
| Telegram 已連結卻無聊天室 | 先向 Bot 按 Start 或在它可讀取的群組發新文字，再按載入；仍沒有可手動加入數字 ID |
| Telegram 群組收不到文字 | 確認 Bot 在群內，具管理權限或適當隱私模式；核對作者及關鍵字。受保護內容與一般 Bot訊息不轉；媒體需另啟用 |
| Telegram Webhook 警示 | 本版不自行刪除 Webhook；改用專用 Bot，或由原服務管理者處理 |
| Telegram 409 | 同一 Bot 有其他 getUpdates 程序；停止另一服務或改用專用 Bot |
| Telegram 401／403 | 檢查 Token 有效性、Bot 是否被封鎖、是否在聊天室及有發送權限；停止後更正設定 |
| Telegram／Discord 429 | 有效平台等待期限會保存並自動重試；同 Bot 平台其他路線也等待。不要靠重啟或重複規則增加負載 |
| Telegram 收訊紀錄／上限警示 | 收訊寫入失敗、損壞或達 50,000 則會停止接收；保留資料供檢查，不可直接刪檔重跑 |
| 配對 send_uncertain／sending／blocked | 發送結果不明，該配對跨重啟持續暫停。先人工核對目的是否收到；停止後展開人工處理，逐筆確認收到或略過；不能確認就保持暫停。處理後原規則可接續其餘待送，不重送不明文字 |
| Telegram 連線未建立，訊息尚未送出 | DNS、拒絕連線或 TLS 失敗，請求確定沒有送到 Telegram；待送已保存，等待後自動重試（5 秒起倍增，最長 5 分鐘），不會鎖定路線。持續出現時檢查網路、DNS、Proxy 與系統時間 |
| 沒收到 Telegram 健康告警 | 到「設定與診斷 → 系統健康告警」確認已啟用、聊天室 ID 正確、Bot 在該聊天室（私訊需先按 Start），再按「發送測試告警」。告警只在異常開始、內容改變或 6 小時後重送；網路中斷期間送不出，恢復後下一次檢查會補送 |
| 開機後服務沒有起來 | 看 `%LOCALAPPDATA%\LinePort\autostart.log`：每次登入啟動都會記錄啟動的版本與錯誤摘要。出現「較新的 LinePort 寫入」表示舊版被擋下覆寫，請改用較新版；沒有任何紀錄表示啟動捷徑沒有執行，到 Windows 設定→應用程式→啟動確認 |
| 看門狗沒有拉起服務 | 看 `%LOCALAPPDATA%\LinePort\watchdog.log`。「circuit open」表示 15 分鐘內已重啟 3 次仍失敗，看門狗暫停，請改看 autostart.log 與頁面狀態；手動停止轉送後看門狗不會重新開始轉送。排程工作由 `yomi-probe\install-watchdog.ps1` 安裝（`-DryRun` 先預覽、`-Uninstall` 移除） |
| journal | 紀錄不能寫入或末行不完整；停止、保留原檔，檢查磁碟空間與權限 |
| 系統匣燈號是紅色 | 滑鼠停在圖示上看原因：「待核對」到人工處理逐筆核對；「本機服務沒有回應」等看門狗重啟或重新開啟 LinePort。右鍵「重啟轉送」只做停止再開始，不會處理不明發送 |
| 換版時出現「權限讀不到它的命令列」 | 舊服務以系統管理員或其他 Windows 帳號執行，新版無法安全辨識，所以沒有停止它。用同樣身分關閉舊 LinePort，或以系統管理員開啟工作管理員結束提示中的 PID，再重新開啟 |
| 18766 舊程序占用 | 從原 checkout 使用 stop-relay.ps1；被拒絕時核對原終端及程序命令列，不要關全部 Node |
| 更新後仍舊頁面 | 停止背景程序與原 npm start，再於新版目錄啟動並重新整理 |
| forwarded 增加卻沒看見 | 成功數只代表發送回應與本機紀錄保存，不代表接收者已讀；核對實際目的 ID 與篩選條件 |
| 加入指定發訊者後完全沒有訊息 | 固定 ID 必須屬於目前來源；用規則模擬輸入 ID 及通知文字。最近人員不包含所有成員；匿名 Telegram 來源只能辨識聊天室 |
| 有效通知含謝謝卻被略過 | 移除過度寬鬆的排除字；改用指定作者與實際通知關鍵字。已略過的訊息不自動重算 |
| 時段外仍有待送 | hold 保留至下一時段；skip 依原訊息時間略過。若訊息已過時，先停止核對，不要擅自清佇列 |
| 圖片／檔案路線暫停 | 看路線警告：「附件下載…失敗，尚未呼叫目的發送」表示還沒送出，待送保留，確認來源附件還在、LINE 已登入、網路正常後停止再啟動即可；「發送結果不明」照一般不明訊息逐筆人工核對。大小未知的附件下載時才發現超過上限也會停在這裡 |
| 收到「附件未轉送：…」通知 | 附件超過目的上限（圖片 10 MB、檔案 50 MB、Discord 10 MB、Telegram 來源轉 LINE／Discord 20 MB）或格式不支援，改送檔名與大小通知，請到來源查看原檔 |
| v1.1.0 以前 LINE 圖片變成一串 JSON 文字 | 舊版會把 E2EE 圖片／檔案解密後的 JSON（含該附件的解密金鑰）當文字轉出，v1.2.0 已修正：沒開附件的規則不再轉送；開了附件改送真正的圖片／檔案。目的端已收到的舊 JSON 建議手動刪除 |
| Discord 附件發送被拒（403／413） | Bot 需要「附加檔案」權限；413 表示超過伺服器上傳上限。Discord 連線未建立（DNS、拒絕連線）時與 Telegram 一樣自動重試，不再鎖定路線 |
| Discord 頻道檢查成功但發送不明 | 只讀檢查不能證明 SEND_MESSAGES；核對 Bot 在伺服器的權限與目的是否已收到。停止後逐筆人工處理，不直接重送 |
| DPAPI 讀取失敗 | 保留受保護檔及舊檔，核對原 Windows 帳號；換機需停止後重新連結。程式不自動退回舊 Token，勿刪檔繞過保護 |
| 容量達上限 | 停止轉送後到「設定與診斷」按「停止後安全壓縮紀錄」：會先建立並驗證私人封存，再逐檔換成精簡紀錄（保留去重、待送、不明發送與回覆對照）。壓縮中止時原資料不變；勿手動刪去重紀錄 |
| 停擺很久，恢復後不想補送舊訊息 | 人工處理時選「確認收到，快轉到現在」：此路線已排隊的訊息與停擺期間的來源舊訊息都不再送出，被略過的 ID 寫在 `lineport-review-*.jsonl`。要補送就選「確認收到，補送後續積壓」 |

來源與目的失敗隔離。整體 running 也應配合個別來源、配對與訊息篩選查看；首次基準期間的文字會略過。

背景程序即使 failed，仍可能提供狀態頁。LINE 發生限制或異常驗證時先停止；勿以密集重試處理。[使用與更新](USAGE.md)
