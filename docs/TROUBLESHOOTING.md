# 疑難排解

查看頁面各來源／配對警示，或 http://127.0.0.1:18766/status。回報時提供版本、phase、stage 與去識別化錯誤；不要上傳 Token、PIN、登入目錄或私人訊息。

| 現象 | 處理方式 |
| --- | --- |
| 手機無授權提示 | 確認同一帳號、允許其他裝置登入；原申請結束後再申請，不要並行登入 |
| data_permissions | 檢查 LOCALAPPDATA、Windows 權限與資料目錄連結；勿改成公開共用目錄 |
| LINE 登入不存在／失效 | 先停止轉送，再恢復或重新手機授權 |
| 可以列群組但收不到 | 等首次基準完成後發全新文字；本輪掃描包含舊訊息。看各路線已處理、新候選、符合條件與條件排除數，並核對指定人員、必要字、排除字及排程。符合條件後仍須看待送／平台接受／發送不明；核對解密失敗與時間警示。已排除訊息不自動重算 |
| e2ee_keys | 缺少帳號加解密資料；停止並重新手機授權 |
| destination_e2ee | 目的加密準備失敗；確認網路與官方 LINE 可發訊，再停止重啟；仍失敗時重新授權 |
| LINE 個人不在選單 | 目前只列出好友，官方帳號排除；重新載入群組與好友 |
| 同名群組 | 依選項後方 ID 辨識；新版不要求名稱唯一 |
| 重複／循環規則被阻擋 | 檢查所有啟用規則；不可自我轉送、重複配對或形成回到原來源的路徑 |
| 來源讀取警示／degraded | 該來源採退避重試；檢查連網、登入及時間，其他來源仍可運作 |
| LINE 補讀失敗或超過 1,000 則 | 保留紀錄，檢查停機時間與訊息量；本版不能保證補齊完整歷史 |
| Telegram 已連結卻無聊天室 | 先向 Bot 按 Start 或在它可讀取的群組發新文字，再按載入；仍沒有可手動加入數字 ID |
| Telegram 群組收不到文字 | 確認 Bot 在群內，具管理權限或適當隱私模式；核對作者及關鍵字。受保護內容與一般 Bot訊息不轉；媒體需另啟用 |
| Telegram Webhook 警示 | 本版不自行刪除 Webhook；改用專用 Bot，或由原服務管理者處理 |
| Telegram 409 | 同一 Bot 有其他 getUpdates 程序；停止另一服務或改用專用 Bot |
| Telegram 401／403 | 檢查 Token 有效性、Bot 是否被封鎖、是否在聊天室及有發送權限；停止後更正設定 |
| Telegram／Discord 429 | 有效平台等待期限會保存並自動重試；同 Bot 平台其他路線也等待。不要靠重啟或重複規則增加負載 |
| Telegram 收訊紀錄／上限警示 | 收訊寫入失敗、損壞或達 50,000 則會停止接收；保留資料供檢查，不可直接刪檔重跑 |
| 配對 send_uncertain／sending／blocked | 發送結果不明，該配對跨重啟持續暫停。先人工核對目的是否收到；停止後展開人工處理，逐筆確認收到或略過；不能確認就保持暫停。處理後原規則可接續其餘待送，不重送不明文字 |
| journal | 紀錄不能寫入或末行不完整；停止、保留原檔，檢查磁碟空間與權限 |
| 18766 舊程序占用 | 從原 checkout 使用 stop-relay.ps1；被拒絕時核對原終端及程序命令列，不要關全部 Node |
| 更新後仍舊頁面 | 停止背景程序與原 npm start，再於新版目錄啟動並重新整理 |
| forwarded 增加卻沒看見 | 成功數只代表發送回應與本機紀錄保存，不代表接收者已讀；核對實際目的 ID 與篩選條件 |
| 加入指定發訊者後完全沒有訊息 | 固定 ID 必須屬於目前來源；用規則模擬輸入 ID 及通知文字。最近人員不包含所有成員；匿名 Telegram 來源只能辨識聊天室 |
| 有效通知含謝謝卻被略過 | 移除過度寬鬆的排除字；改用指定作者與實際通知關鍵字。已略過的訊息不自動重算 |
| 時段外仍有待送 | hold 保留至下一時段；skip 依原訊息時間略過。若訊息已過時，先停止核對，不要擅自清佇列 |
| 圖片／檔案路線暫停 | 核對同 Bot Telegram → Telegram、圖片 10 MB／檔案 50 MB、說明含前綴 1,024 字元；跨 LINE 尚未支援。大小未知時保留原訊息並調整規則 |
| Discord 頻道檢查成功但發送不明 | 只讀檢查不能證明 SEND_MESSAGES；核對 Bot 在伺服器的權限與目的是否已收到。停止後逐筆人工處理，不直接重送 |
| DPAPI 讀取失敗 | 保留受保護檔及舊檔，核對原 Windows 帳號；換機需停止後重新連結。程式不自動退回舊 Token，勿刪檔繞過保護 |
| 容量達上限 | 停止並保留完整私人資料，檢查磁碟及已知紀錄大小。封存不釋放空間；檔案大小上限需後續安全壓縮，重啟不會解除，勿刪去重紀錄 |

來源與目的失敗隔離。整體 running 也應配合個別來源、配對與訊息篩選查看；首次基準期間的文字會略過。

背景程序即使 failed，仍可能提供狀態頁。LINE 發生限制或異常驗證時先停止；勿以密集重試處理。[使用與更新](USAGE.md)
