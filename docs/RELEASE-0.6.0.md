# v0.6.0：指定發訊者、隔離等待、保留資料

2026-10-09。接續 v0.5.0；沒有新增 npm 依賴、資料庫 Schema 變更或不可逆遷移，也沒有自動啟動真實服務。

- 每個來源可指定最多 20 個發訊者 ID，配合包含／排除關鍵字；純文字模擬回報具體排除原因。人員清單來自近期可讀訊息，不是完整群組成員表。
- 規則搜尋、複製為暫停規則、訊息關鍵字範本。複本需調整路線後才啟用，禁止重複啟用配對。
- 台北時段預設關閉；時段外可保留待送，或按訊息時間略過並保存 ID 證據。跨午夜屬於開始日，結束時刻不包含；已入列內容不重新套用作者／關鍵字。
- 圖片／檔案預設關閉，只支援同一 Bot 的 Telegram → Telegram。圖片 10 MB、檔案 50 MB（十進位）、說明含前綴 1,024 字元；大小未知或格式不符時暫停該路線。使用同一 Bot 的 file_id，不下載原檔、不建立媒體暫存。
- Discord 採官方 Bot API，選用的一般伺服器文字目的，最多 2,000 字元。停用自動提及及連結預覽；只讀檢查不證明發訊權限。明確 429 保存等待期限，其他不明發送仍暫停。
- 來源與待送佇列獨立工作，讀取逾時不產生重疊請求；不同目的可並行，同目的仍序列化。已保存待送可在來源斷線時繼續處理。
- 容量盤點不讀憑證，只統計規則及已知紀錄。接近上限警告、達上限停止；私人封存複製原紀錄並產生 SHA-256 manifest，不刪除、輪替或清空任何資料。
- Telegram／Discord Bot Token 可選 Windows CurrentUser DPAPI；受保護檔損壞時不退回舊 Token，後續重新連結維持保護。舊明文檔保留，LINE 登入／E2EE 不遷移。

## 下載與手動更新

[版本頁](https://github.com/b40609/LinePort/releases/tag/v0.6.0) · [LinePort-v0.6.0.zip](https://github.com/b40609/LinePort/releases/download/v0.6.0/LinePort-v0.6.0.zip) · [SHA256SUMS.txt](https://github.com/b40609/LinePort/releases/download/v0.6.0/SHA256SUMS.txt)

固定版本原始碼 ZIP，需要 Node.js 與 npm；沒有 EXE 或自動更新。SHA-256 是完整性核對，沒有發行簽章。

1. 停止轉送、關閉原 Node 程序，不同版本不得同時共用資料目錄。
2. 保存設定備份，另私下複製完整 `%LOCALAPPDATA%\LineCallYomiProbe`。設定備份及封存都不能取代完整私人備份；完整資料包含憑證與私人訊息，禁止分享。
3. 下載 ZIP 與摘要，執行以下指令，比對完整 64 字元 SHA-256。
4. 解壓至新資料夾，保留舊程式及私人備份；在新版 `yomi-probe` 執行 `npm.cmd ci --ignore-scripts`、`npm.cmd test`，確認後自行執行 `npm.cmd start`。
5. 重新整理頁面，恢復連結、核對規則、指定人員及平台權限，再按開始。DPAPI 憑證換電腦或 Windows 帳號時需重新連結。

```powershell
Get-FileHash .\LinePort-v0.6.0.zip -Algorithm SHA256
Get-Content .\SHA256SUMS.txt
```

v0.4.0／v0.5.0 queued、retry、人工決策可繼續讀取。新媒體採帶 payloadVersion 的 media_queued，未知版本拒絕載入。**不可直接降版處理新版資料**：舊版無法理解媒體／人工決策，且可能忽略指定作者、時段或讀取保留的舊明文 Token。需要回復時先停止所有程序，再規劃一致的程式與完整私人資料備份恢復，不能只換單一紀錄。

## 容量與保留政策

單一紀錄保守讀取上限 16 MiB；已知規則／JSONL 合計 256 MiB；可用空間低於 64 MiB 停止新收件與發送。紀錄到 80% 或空間低於 256 MiB 預警。Telegram 收件上限另為 50,000 則，40,000 則預警；每配對待送最多 1,000 則，未入列不推進 checkpoint，後續補讀仍受平台保留期限限制。

待送、去重、offset、人工決策與輸出 ID 全部保留，不設定自動刪除期限。私人封存留在受保護資料目錄，包含訊息與可識別 ID，不可分享；不含憑證、不釋放空間。達紀錄大小上限後仍需後續安全壓縮設計，不能靠封存或重啟解除。程式碼未新增持續增長的 console 檔案日誌；主要增長來源是 JSONL 與記憶體去重集合。檔案上限不等於精準記憶體配額。
