# 使用與維護

## 來源、目的與測試

1. 開啟登入頁，恢復登入並讀取群組列表。
2. 選取群組，複製完整群名欄位；不需手打 emoji。
3. 雙擊 `啟動自動轉送.cmd`，貼上來源與目的名稱。
4. 在 http://127.0.0.1:18766/status 確認 `phase=running`。
5. 在來源發一則新的文字，例如 `測試 001`，確認目的收到；相同文字但不同訊息 ID 仍會分別轉送。

目的發訊者是登入的個人帳號。來源不需要加 Bot，但不能保證平台或群組成員無法察覺自動轉送。現階段只轉送可讀文字，沒有關鍵字或指定發訊者篩選，也不支援 Telegram、圖片、OpenChat。

登入網頁的自動讀取功能只是預覽。實際轉送由獨立背景程序執行；關閉瀏覽器不會停止。預覽最多保留 5,000 則於記憶體，重新整理會清空，需及早手動匯出。匯出的訊息是明文，應自行妥善保管。

## 狀態欄位

| 欄位 | 意義 |
| --- | --- |
| `phase` | starting：初始化；running：運作中或等待重試；failed：已停止轉送，狀態頁仍可開啟 |
| `stage` | 最近執行階段；failed 時可據此排查 |
| `polls` / `lastPoll` | 本次程序成功讀取次數／時間，沒有新文字也會更新 |
| `forwarded` | 本次程序收到發送成功且包含訊息 ID 的回應數，不代表接收者已讀 |
| `uncertain` | 發送失敗或回應缺 ID，無法確認目的是否收到；不自動重送 |
| `errors` / `consecutiveErrors` | 本次程序累計／連續錯誤數 |
| `retrySeconds` | 讀取錯誤後等待秒數；成功後歸零 |

上述計數在程序重啟後歸零，去重紀錄仍會保留。正常每輪完成後等待 3 秒；同批多則文字間至少等待 1 秒。讀取連續失敗分別等待 3、6、12、24 秒，第 5 次失敗停止。發送結果不明或紀錄寫入失敗立即停止。

## 停止、切換與重新啟動

在專案根目錄執行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\yomi-probe\stop-relay.ps1
```

此指令只會結束由這份專案啟動器啟動、占用 18766 的 `relay.mjs`；不會關閉所有 Node 程序。若你手動使用 `node relay.mjs` 啟動，請在原終端按 Ctrl+C。停止時正在傳送的訊息可能結果不明，重啟不會自動補送該 ID。

切換群組：先停止，再雙擊 `啟動自動轉送.cmd` 貼上新名稱。啟動器偵測到另一條規則正在執行會報錯，不會默默沿用舊群組。

同一條規則重新啟動沿用基準，可能補送停機期間仍在最近 50 則內的未處理文字。若想完全略過停機訊息，需要另行設計重設基準流程；不要直接刪除或修改紀錄。

## 更新程式

1. 停止背景轉送；關閉登入服務對應的程序或原 `npm start` 終端。只關閉網頁不等於停止登入服務。
2. 更新原始碼。若有自訂修改，先保留備份，不使用 `git reset --hard`。
3. 在 `yomi-probe` 執行 `npm ci --ignore-scripts`、`npm test`。
4. 重新啟動登入服務與轉送，確認狀態頁與新訊息測試。

新程式不會自動替換已在執行中的程序。v2 的背景狀態含 `version: 2`；舊版沒有此欄位。初次升級會為舊紀錄追加帳號及群組 ID 的雜湊識別，之後若識別不符將拒絕啟動。舊版基準是否曾部分寫入，無法事後完整證明。

## 資料與備份

資料位置：`%LOCALAPPDATA%\LineCallYomiProbe`。內有敏感登入資料、E2EE 金鑰與 `relay-*.jsonl` 處理紀錄。紀錄包含基準、訊息 ID、規則識別雜湊及處理結果，不包含訊息文字，不能當作聊天備份。

目前沒有自動清理紀錄、完整歷史補抓、開機自動啟動或完整訊息封存。紀錄會隨使用增長；搬移或保管備份時應視為敏感資料。不要同時用多份專案操作同一組登入資料，也不要在轉送中重做登入。

`test-relay.mjs --send-latest` 是開發用的真實發訊工具，會傳送一則歷史文字；日常測試不需要執行它。
