# 使用教學

## 規則設定

開啟 http://127.0.0.1:18765/，載入需要的平台聊天室。LINE 使用「載入 LINE 群組與好友」；一般群組與好友以 ID 辨識，同名可分開選。

1. 輸入規則名稱。
2. 選擇來源與目的；按住 Ctrl 可多選。每個來源都會轉到全部目的。
3. 視需要展開「進階設定：指定發訊者、內容與時段」。可先用規則模擬核對目的與內容，不會發訊。
4. 按「新增並保存規則」。可新增其他規則，或編輯／暫停既有規則。
5. 按「開始轉送」，等基準完成後發送一則新文字測試。

包含關鍵字：每行一個，符合任一個才轉送；留空表示不限。排除關鍵字優先；大小寫不影響比對，採一般文字包含判斷，不支援正規表示式。前綴直接加在文字前，空格由使用者輸入。

上限為 30 條規則，每條最多 10 個來源與 10 個目的，啟用配對合計最多 100 組。禁止自我轉送、重複啟用配對與循環。預設轉文字；Telegram 媒體說明可當文字。圖片／檔案需另行啟用且只限同一 Bot 的 Telegram → Telegram；貼圖及跨 LINE 媒體未支援。

首次啟動略過基準快照內的歷史訊息。相同規則 ID 與帳號重啟沿用紀錄；改名稱不重設，新增規則則建立新基準。不同 ID 的相同文字會分別處理。

## 分析師與規則管理

選取來源，展開進階設定；逐一選擇要限制的來源，載入最近發訊者，加入分析師固定 ID（最多 20 人）。留空表示不限制；填入後缺少或不符人員 ID 的訊息不會通過。最近清單不是完整成員表，未出現可手動填 ID；不要用暱稱代替。Telegram 匿名管理員／頻道可能只有聊天室身分，不能從 sender_chat 辨識特定自然人。

Call 訊範本填入常見關鍵字，可依實際文字修改。不要直接將「謝謝」列為排除字，否則有效 Call 訊結尾含謝謝也會整則略過。模擬輸入發訊者 ID、文字與台北時間，會顯示目的、內容及具體不轉送原因；目前只模擬第一個選取來源的純文字。[多來源設定範例](CALL-ROUTING.md)

規則搜尋可找名稱、端點及關鍵字；複製規則預設暫停。需調整來源／目的後再啟用，不能建立重複啟用配對。

## 時段與 Telegram 媒體

新增功能預設關閉。時段只使用台北時間，星期 0 為週日、6 為週六；跨午夜歸開始日，結束時刻不包含。「保留待送」依實際發送時間等待，重啟仍保留；「略過」依訊息時間保存略過證據，不再補送。Call 訊可能因延遲失去時效，未確認需求前保持關閉。已待送內容不重新套用作者／關鍵字；實際發送仍遵守目前時段。

圖片最多 10 MB、檔案最多 50 MB（十進位），說明含前綴最多 1,024 字元；大小未知／超限時暫停該路線。採同一 Bot 的 file_id 重用，不下載暫存。關鍵字只比對媒體說明；無說明圖片可能被排除。受保護、付費、限時內容不轉送；相簿不保證整組，媒體模擬、回覆關聯及跨 LINE 媒體尚未提供。

## Discord（選用目的）

展開平台連結的 Discord 選項，填入自己的專用 Bot Token，連結後加入數字頻道 ID。只支援一般伺服器文字頻道作目的，沒有來源、私訊、討論串或媒體。Bot 需檢視頻道及發訊權限；只讀檢查不會發訊，也不能證明可發訊。含前綴最多 2,000 字元，停用自動提及與連結預覽。明確 429 保存等待期限，其他發送不明暫停人工核對。

Telegram／Discord 可選 Windows DPAPI；保存後 Token 輸入欄清空。舊明文檔為回復保留，受保護檔損壞不自動退回舊 Token；換 Windows 帳號或電腦請重新連結。

## Telegram

使用自己的專用 Bot。由 [BotFather](https://t.me/BotFather) 建立，將 Token 輸入本機頁面，按「連結並保存」。欄位會清空，API 不回傳保存的 Token。

| 聊天室 | 設定 |
| --- | --- |
| 個人私訊 | 對方先向 Bot 按 Start 或發訊，Bot 才能接觸該私訊 |
| 群組來源 | 加入 Bot；為讀取一般群友文字，可授予管理員權限或在 BotFather 調整隱私模式 |
| 群組目的 | Bot 必須在群內且有發訊權限 |
| 頻道來源／目的 | 加入 Bot 並依讀取、發文需求配置頻道管理權限 |

在來源群組發新文字，或向 Bot 按 Start，接著按「載入 Bot 聊天室」。它只從目前尚待處理的更新取得聊天室資料，不一定列出 Bot 加入過的所有聊天室。沒有出現時，可手動填入數字聊天室 ID，再按「加入選單」。不支援網址或 @username。

請勿讓同一 Bot 同時由其他程式執行 getUpdates。本版採長輪詢，Telegram 有 Webhook 時會阻止來源啟動，不會自行刪除 Webhook。建議專用 Bot，避免搶走其他服務的更新。

LINE → Telegram、Telegram → LINE 與同平台轉送均可。Telegram Bot 收到哪些訊息，取決於權限與隱私模式；不會讀取你的全部個人聊天。本工具排除 Bot 發出的訊息及受保護內容。

參考：[官方 FAQ](https://core.telegram.org/bots/faq)、[getUpdates／sendMessage 文件](https://core.telegram.org/bots/api)。

## 停止與切換

按「停止轉送」，等「已停止」再修改規則或平台設定。關閉網頁不會停止背景程序；電腦需持續連網、不休眠。修改規則需停止後保存，再啟動。

停止時正在發送的訊息可能結果不明。未完成 sending 或 uncertain 紀錄會使該配對重啟後仍受阻，不能靠重啟自動清除。停止後展開「發送結果不明：人工處理」，逐筆核對目的並選確認收到或略過。不確定時保留暫停，不重送。再依 [疑難排解](TROUBLESHOOTING.md) 處理。

網頁無法操作時，於專案根目錄執行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\yomi-probe\stop-relay.ps1
```

腳本只處理此 checkout 啟動器啟動的指定 `relay.mjs`。手動啟動程序請到原終端按 Ctrl+C。不要一次關閉所有 Node 程序。

## 訊息預覽

選取 LINE 聊天室，按「讀取最近訊息」。自動預覽每 10 秒讀取，不負責發送，也不包含 Telegram。頁面最多保存 5,000 則，重新整理會清空；匯出 JSON 是明文。

## 狀態與故障隔離

頁面列出每個來源成功讀取時間、訊息數、解密失敗及警示，每組來源／目的另顯示待送、成功、略過與受阻原因。18766 的 `/status` 提供版本 3 狀態：

| 欄位 | 意義 |
| --- | --- |
| phase | starting 初始化；running 正常；degraded 部分受阻；failed 無可運作配對 |
| routes | 每組配對的狀態、待送與計數 |
| sources | 各來源的成功讀取次數、時間及警示 |
| forwarded | 發送回應含訊息 ID，且結果保存成功的數量；不是接收者已讀數 |
| revision | 啟動時載入的設定版本摘要（18766 原始狀態） |

計數在程序重啟後歸零，保存紀錄保留。來源讀取失敗依序退避 3、6、12、24、48、60 秒，之後維持 60 秒重試，不影響其他來源。發送不明、缺少回應 ID 或紀錄寫入失敗會暫停相關配對，其他目的仍可繼續。

LINE 近期 50 則不足時會分頁追查，最多 1,000 則；追不到基準、無法分頁或游標異常會顯示讀取警示。這不等於完整歷史備份或保證停機後全數補送。

## 更新

v0.5.0 可展開「設定備份、還原與安全診斷」。設定備份不含登入與 Bot Token，但含私人聊天室名稱／ID，請私下保存。選取備份會先驗證並顯示規則摘要；停止後按「確認還原規則」，原設定會先另存資料目錄。它不還原待送與去重進度，也不會啟動服務。安全診斷僅含版本、旗標與計數，適合回報問題，與全文訊息匯出不同。

朋友可以直接下載 [v0.6.0 ZIP](https://github.com/b40609/LinePort/releases/download/v0.6.0/LinePort-v0.6.0.zip)；先依 [更新說明與 SHA-256](RELEASE-0.6.0.md) 核對下載檔；停止後私下備份完整資料目錄，保留舊程式：

1. 先停止轉送，在 `npm start` 原終端按 Ctrl+C。
2. 下載並解壓新版；自行修改的程式檔先備份。
3. 在新版 `yomi-probe` 執行下列指令。
4. 重新整理頁面，恢復登入並載入聊天室，再測試新文字。

```powershell
npm.cmd ci --ignore-scripts
npm.cmd test
npm.cmd start
```

登入資料存於外部的 `%LOCALAPPDATA%\LineCallYomiProbe`，更換程式資料夾不會清除登入。從單配對舊版升級到 v0.3.0，需在新版頁面重新建立規則；舊紀錄保留，但不自動轉成新規則，新規則首次略過歷史。v0.3.0 之後相同保存規則沿用紀錄。

Node 程序必須重啟才套用新版。舊背景程序若占用埠，先使用停止腳本或核對原終端及命令列。搬到新資料夾時，舊程序需從舊資料夾停止，腳本不會跨 checkout 結束其他程序。

## 本機資料

資料目錄保存登入／E2EE、規則、Bot 憑證、配對 JSONL、輸出 ID 與 Telegram 收訊紀錄。Bot Token 可選 DPAPI；LINE 登入／E2EE、訊息、舊明文 Token 及封存仍未加密，使用 Windows DACL 限制存取。

「本機容量與私人封存」提供容量檢查；停止後可複製已知紀錄、保留原檔並產生 SHA-256 manifest。這是含私人訊息與 ID 的封存，不是安全診斷或完整備份，不能分享，也不釋放容量。單檔 16 MiB、已知紀錄合計 256 MiB 或可用空間低於 64 MiB 時停止，尚未提供安全壓縮；勿自行刪資料解除。

Telegram 更新先寫入並同步至磁碟，再推進下一次 getUpdates 的 offset；收訊紀錄損壞或寫入失敗會停止讀取。選定來源文字累計最多 50,000 則，達上限停止接收，尚未提供安全輪替。不要自行刪改處理紀錄，以免破壞去重。
