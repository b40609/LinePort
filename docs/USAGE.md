# 使用教學

## 設定與測試

在 http://127.0.0.1:18765/ 連結帳號、載入群組，選擇來源與目的後按「開始轉送」。等「轉送中」，在來源發送 `測試 001`，確認目的收到。

首次啟動略過當時的歷史訊息；同一規則重啟會沿用紀錄，可能補送停機期間仍在最近 50 則內的新文字。不同 ID 的相同文字會分別轉送。

來源與目的必須不同且群名唯一。目的訊息的發訊者是登入帳號。目前只支援一般群組文字，不支援 OpenChat、Telegram 或關鍵字篩選。

## 停止與切換

按「停止轉送」，等狀態顯示「尚未啟動」，再選擇新群組並啟動。關閉瀏覽器不會停止轉送；電腦需保持連網、不休眠、不登出。

停止時正在發送的訊息可能結果不明，重啟不會自動重送該 ID。不要在轉送中重新授權登入或同時執行多份專案。

若網頁無法操作，可在專案根目錄執行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\yomi-probe\stop-relay.ps1
```

腳本只允許結束此專案啟動器啟動的指定 `relay.mjs`。手動 `node relay.mjs` 啟動的程序，請至原終端按 Ctrl+C。

## 訊息預覽

選擇「預覽群組」，按「讀取最近訊息」；「自動更新預覽」每 10 秒讀取一次，不負責發送。頁面保留最多 5,000 則，重新整理會清空。按「匯出 JSON」下載本次預覽，匯出內容為明文。

## 狀態

畫面顯示本次程序的轉送、成功讀取及錯誤計數。詳細狀態位於 http://127.0.0.1:18766/status：

| 欄位 | 意義 |
| --- | --- |
| `phase` | starting：初始化；running：輪詢中；failed：已停止排程 |
| `stage` | 最近階段，失敗時用於排查 |
| `forwarded` | 收到包含訊息 ID 的成功發送回應數，非接收者已讀數 |
| `polls` / `lastPoll` | 成功讀取次數／時間 |
| `uncertain` | 無法確認送達，不會自動重送 |
| `errors` / `retrySeconds` | 累計錯誤／讀取重試等待秒數 |

計數於程序重啟歸零；去重紀錄保留。讀取失敗依序等待 3、6、12、24 秒，第 5 次連續失敗停止。發送結果不明或紀錄寫入失敗立即停止。處理方式見 [疑難排解](TROUBLESHOOTING.md)。

## 更新

1. 停止轉送，結束登入服務的 `npm start` 終端；若由 CMD 背景啟動，確認工作管理員命令列後只結束此專案的 `server.mjs`。
2. 更新原始碼；自行修改的檔案先備份。
3. 在 `yomi-probe` 執行 `npm.cmd ci --ignore-scripts`、`npm.cmd test`、`npm.cmd start`。
4. 重新整理網頁，恢復登入、選擇群組，再以新文字測試。

已執行中的 Node 程序不會自動套用更新。若畫面顯示「舊版服務執行中」，先停止舊版轉送；停止腳本拒絕時，至原終端停止或核對該程序命令列，不要一次結束所有 Node 程序。

## 資料

`%LOCALAPPDATA%\LineCallYomiProbe` 包含敏感登入／E2EE 資料與 `relay-*.jsonl`。處理紀錄只有基準、訊息 ID、規則識別與結果，不是全文備份；不要直接刪除或修改，以免破壞去重。

目前沒有完整歷史補抓、開機自啟動或紀錄輪替。詳細流程見 [架構](ARCHITECTURE.md)，保存限制見 [安全說明](../SECURITY.md)。
